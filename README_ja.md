# 📊 RepoVote エンジン

**Gitリポジトリを活用した分散型意思決定**

**RepoVote Engine**へようこそ。これは革新的なオープンソースプラットフォームで、投票プロセスをGitHubリポジトリに直接組み込むことにより、コミュニティがどのように集団的な意思決定を行うかを再考します。外部の認証システムを必要とする従来のアンケートツールとは異なり、RepoVote Engineは既存のGitインフラを活用します。すべての投票はリポジトリ内に存在する構造化されたCSVファイルであり、各コミットは1票として扱われ、マージリクエストは投票結果の再集計の機会となります。

あなたのリポジトリを単なるコードベースとしてだけでなく、常に更新され続けるガバナンス台帳として考えてみてください。RepoVote Engineは、静的なバージョン管理を動的な審議エンジンへと変え、コントリビューターたちが既に信頼しているGitコマンドやプルリクエスト、ブランチ保護機能といったツールをそのまま使って投票できるようにします。これは単なる別のポーリングウィジェットではなく、**「あなたのコード、あなたのルール、あなたの民主主義」**という哲学的な転換なのです。

## 🌟 RepoVote Engineが存在する理由

現代のコラボレーションツールには、**分断されたアイデンティティ**（別のアプリにもログインする必要があること）、**見えない履歴**（投票期間が終了すると投票記録が消えてしまうこと）、**中央集権的な管理**（プラットフォーム運営者が結果を変更できてしまうこと）という3つの致命的な欠点があります。RepoVote Engineは、すべての投票を変更不可能なGitオブジェクトに紐付けることで、これら3つの問題をすべて解消します。

開発者が投票する際、指定されたブランチにコミットを作成します。そのコミットのハッシュがタイムスタンプとなり、GPG署名が投票者IDとなり、投票用CSVとの差分が彼らの選択内容となります。データベースもセッションクッキーも、不明瞭なバックエンドも存在しません。Gitの履歴そのものが監査トレイルとなるのです。

このリポジトリには、CSV形式の投票を処理し、GitHubのOAuthスコープに基づいて投票者の資格を検証し、承認された結果を自動的に標準的な`votes/main`ブランチにマージするワーカーランタイムが含まれています。これはサーバーレス関数、GitHub Action、または自前でホストされるNode.jsサービスとして実行されるように設計されています。

### 📋 前提条件

RepoVote Engineをデプロイする前に、お使いの環境が以下をサポートしていることを確認してください：

- ブランチ保護ルールを設定したGitHubリポジトリ（必須ではありませんが強く推奨されます）  
- GitHub OAuthアプリの認証情報（Client IDおよびClient Secret）へのアクセス権  
- ワーカー用としてNode.jsランタイム（バージョン18 LTS以降）  
- BOMマーカーを含むUTF-8エンコードファイルを処理できるCSVパーサー

### ⚙️ 設定アーキテクチャ

RepoVote Engineは「コードとしての設定」という考え方に基づいています。すべての設定値は、リポジトリのルートにある`voteconfig.yml`ファイルに保存されます。こちらが最小限の例です：

```yaml
polls:
  - path: polls/feature-priority.csv
    voters: members
    approval_threshold: 0.6
    deadline: 2026-12-31T23:59:59Z
    anonymity: true
identity:
  provider: github
  required_org: your-org-name
  min_account_age_days: 30
output:
  results_branch: votes/consolidated
  notify_on_merge: true
```

初期化時には、すべてのパラメータがJSONスキーマに基づいて検証されます。設定ファイルにタイプミスがある場合、ワーカーは起動を拒否し、正確な行番号を示した詳細なエラーメッセージを出力します。

## 🔑 コア機能

### 🗳️ CSVネイティブ型投票エンジン

各ポーリングは、ユーザーが定義する列を持つシンプルなCSVファイルです。典型的なポーリングの例は次のようになります：

| 提案内容 | 投票者 | 選択肢 | タイムスタンプ |
|----------|-------|--------|-----------|
| 第3四半期のロードマップを支持しますか？ | octocat | はい | 2026-04-12T10:30:00Z |
| 第3四半期のロードマップを支持しますか？ | torvalds | いいえ | 2026-04-12T11:15:00Z |

独自のフォーマットもデータベーススキーマもありません。どんなスプレッドシートツールを使っても投票用ファイルを編集でき、`git add` を使ってコミットし、他のファイルと同様に変更履歴を追跡できます。

### 🔐 GitHub純正の認証方式

RepoVote Engineは、すべての身元認証をGitHubのOAuthフローに委ねています。投票者がセッションを開始すると、GitHubへリダイレクトされて最小限のスコープ（`read:user`および`read:org`）の承認を求められ、戻ってきた後にワーカーがその人のGitHubユーザーID、ユーザー名、および組織への所属状況を含む署名済みのJWTを生成します。

- **シビル攻撃対策**：設定可能な最小アカウント年齢により、遠隔操作による投票を防ぎます  
- **組織単位での投票資格制限**：特定のGitHub組織やチームのメンバーのみが投票できるようにします  
- **1アイデンティティあたり1票の制限**：ポーリングブランチ間でのコミットSHAを重複チェックすることにより実施されます

### 📈 透明性の高い監査トレイル

すべての投票はコミットとして記録されます。コミットメッセージは一定の形式に従っています：

```
[VOTE] アンケート: feature-priority.csv | 選択肢: Reactエコシステム | 投票者: 認証済み
```

コミットツリーには、投票者の行が追加された更新済みのCSVファイルが含まれています。`git log --all polls/feature-priority.csv`を使用することで、投票の全履歴を確認できます。過去の投票を改変しようとする悪意ある試みは、すぐに検出可能な分岐した履歴を生み出します。

### 🌐 複数言語対応のインターフェース

ウェブダッシュボードはブラウザの言語設定を自動で検出し、英語、スペイン語、フランス語、ドイツ語、日本語、韓国語、アラビア語を含む20以上の言語に対応したローカライズされたテキストを表示します。また、投票用の説明文にはUnicodeがサポートされているため、どのような文字体系のテキストでも使用できます。

### 📱 対応性に優れたアクセシブルなUI

軽量なウェブコンポーネントアーキテクチャを基盤としているため、このインターフェースはスマートフォン、タブレット、デスクトップにシームレスに対応します。すべてのインタラクティブ要素はWCAG 2.1 AA規格を満たしており、スクリーンリーダーで投票結果を読み上げられたり、キーボードだけでもナビゲーションが可能であり、色の使い方も`prefers-color-scheme`の設定値を尊重しています。

### 🛡️ 24時間365日のワーカー信頼性

このワーカーには、以下を監視するヘルスチェックエンドポイントが含まれています：  
- Gitリポジトリへのファイルシステムアクセス  
- GitHub APIのレート制限の利用状況  
- JWT署名キーのローテーション  
- CSVファイルの完全性（チェックサム検証）

何らかのチェックに失敗した場合、ワーカーはHTTP 503ステータスを返し、構造化されたアラートを設定可能なウェブフック（例：PagerDutyやSlack）に記録します。

## 📊 用途と比喩

RepoVote Engineを、あなたのコードベースのための**憲法制定議会**と考えてみてください。各CSVファイルは投票提案に相当し、各プルリクエストは議場での討論、そして各マージは可決された法律となります。

| シナリオ | RepoVote Engineの役割 |
|----------|---------------------------|
| **オープンソースプロジェクトのガバナンス** | メンテナーがプルリクエストを通じてRFC提案に投票できるようにする |
| **コミュニティによる機能優先順位の決定** | ユーザーが次に取り組むべき課題に投票し、その投票結果はリポジトリ内に透明性を持って記録される |
| **組織のポリシー策定** | チームのポリシーをCSV投票として保存し、Gitを通じて承認履歴を追跡する |
| **学術研究におけるインフォームド・コンセント** | 変更不可能なコミット履歴を利用して、研究に対するインフォームド・コンセントを記録する |

## 🧩 アーキテクチャ概要

```
┌─────────────────┐     ┌──────────────────────┐     ┌─────────────────┐
│  GitHub OAuth   │◄────│  RepoVote Worker     │────►│  Git Repository  │
│  (身元認証)     │     │  (サーバーレス/自動)   │     │  (アンケートCSV処理)│
└─────────────────┘     └──────────────────────┘     └─────────────────┘
         │                       │                            │
         ▼                       ▼                            ▼
    ユーザーブラウザ           投票処理                     監査ログ（コミット）
```

このワーカーは仲介者として機能し、GitHubを通じてユーザーの認証を行い、参加資格を確認した上で、投票結果を一時的なブランチへのコミットとして記録します。そして、事前に定められた閾値に達した場合、それらの投票結果を最終的な結果ブランチにマージします。
